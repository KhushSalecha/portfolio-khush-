Understanding CPU Scheduling: From FCFS and SJF to Round Robin

Khush Salecha B.Tech AIML Student & Developer

Sep 29, 2026 7 min read

In my second-year Operating Systems coursework at Jain University, one foundational area that completely transformed how I conceptualize computer software was CPU scheduling. Modern users perceive their operating systems as running dozens of applications simultaneously. In truth, single CPU cores switch context between competing processes in nanosecond slices, governed by mathematical scheduling algorithms.

The Anatomy of the Process Control Block (PCB)

Every task managed by the OS kernel is tracked by a Process Control Block (PCB). When an interrupt or timer tick occurs, the CPU must snapshot the active process's Program Counter (PC), CPU registers, memory limits, and I/O status into its PCB before loading the next candidate from the Ready Queue.

Comparing Core Scheduling Strategies

1. First Come, First Served (FCFS)

The simplest non-preemptive algorithm: processes are dispatched strictly in arrival sequence. While trivially easy to implement via a FIFO queue, FCFS suffers heavily from the Convoy Effect. If a single CPU-bound process with a 100ms burst arrives ahead of three quick 2ms I/O tasks, the quick tasks starve in the ready queue, dramatically degrading the average waiting time.

2. Shortest Job First (SJF) & Preemptive SRTF

SJF associates with each process the length of its next CPU burst, prioritizing the smallest burst first. Mathematically, SJF is provably optimal—it yields the minimum average waiting time across any scheduling scheme.

However, pure SJF is difficult to implement in practice because the kernel cannot predict the exact duration of a future CPU burst. Real-world systems approximate burst times using exponential smoothing over historical execution runs.

3. Round Robin (RR)

Designed specifically for time-sharing systems, Round Robin assigns a fixed unit of time known as a time quantum (typically 10 to 100 milliseconds). The ready queue is treated as a circular queue.

  • If the quantum is too large: RR degenerates into simple FCFS.
  • If the quantum is too small: Context switching overhead dominates, causing the CPU to spend more time saving and restoring registers than executing user instructions.

Why This Matters for Software Developers

Understanding process scheduling isn't just an academic exercise. Whether you are managing asynchronous event loops in Node.js, configuring worker threads in Python, or tuning RTOS priority tasks on an ESP32, knowing how the underlying operating system allocates CPU time is crucial for writing non-blocking, responsive software.
